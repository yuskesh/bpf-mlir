# Release scope — v1 feature paths

- Representative compiler-output measurements for F01/F02/F06 used candidate 79c6d12d on three kernels. Defined semantic observations matched C; instruction counts/JIT bytes exceeded that C implementation. These measurements do not broaden scope or performance claims.
- Initial scope dated 2026-09-26; evidence checking found compile/load/execution evidence on three targets for all 22 initially supported rows, with no downgrades. Later v0.3.0–v0.18.0 additions introduced F32–F35 and loader entries L5/L6, expanding F02/F06/F14/F21/F23/F24/F25/F27/L3. v0.19.0–v0.21.0 added no rows but expanded F02 reservation/large-event rejection, F08 static packet-window arguments and F27 stack boundaries, and exercised F21–F25 tutorials.
- Each row is a concrete public semantic **feature path**, stating its program/map/record/loader context rather than claiming the full Cartesian product.
- **Supported** means within v1 scope; **Limited** means supported only under the stated conditions; **Out of scope** makes no v1 support claim.
- Status describes compiler/ELF capability. It does not imply that a particular language binding or loader implementation is included.
- **Enforced** means compiler or a loader that implements requirements checking rejects invalid use. **Documented boundary** means implementation cannot enforce it, e.g. external loaders or unmeasured environments.
- Known unsupported forms are rejected; undecidable conditions use load-time Unknown / BlocksLoad. Unmeasured combinations remain outside claims. External-loader behavior is a documented boundary.

## Loader entry points (context shared by all rows)

| Entry | Load-time checking | Boundary |
| --- | --- | --- |
| Loader implementing the requirements contract | Extract ELF requirements, query target facts, apply declared loader behavior and stop on blocking failures | Separate from compilation; no loader is included in this source package |
| Loader that explicitly bypasses requirements checking | None | May load or silently adapt without the pre-load protections |
| External iproute2 / libbpf / bpftool | Do not read .ebpf_requirements | Kernel load/attach success alone does not prove all declared value contracts |
| Caller map declarations (maps.json) | Bidirectional maps, records, globals and flags | Omitted optional declarations are not checked |

## Gaps identified by the original scope review

- **F13 growth** was once accepted without runtime evidence; now compilation rejects it, requiring direct arith.constant i32 delta≤0.
- **F17/F18/F31 timer/spin-lock records** require preserving opaque field layout; checked loading was demonstrated with a reference binding implementation.
- **F06/F07 non-root limits** fail loudly at load; [non-root documentation](nonroot.md) records known refusals/workarounds and measured privilege combinations.
- The initial22 supported rows had evidence without downgrades. Only F29 lacked C differential evidence because normal/once values are indistinguishable in single-thread C execution. Initial record-rejecting binding evidence for F17/F18 was a manual research record without saved raw output.
